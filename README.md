# Faithful to Whom? Supplementary code

Code for *Faithful to Whom? Auditing Guarantee Erosion When Language Models
Explain Automated Decisions* (anonymous submission).

**A note on names.** The paper calls the audit protocol it introduces
**REACH**, a short name for the whole procedure: generate the explanation a
person would read, parse it back into conditions, and score those conditions
against the classifier. This bundle uses the same name, so `reach-supplementary`
and every mention of REACH below refer to that protocol, not to a different
paper or system.

This bundle contains the code needed to rerun the study: the audit
instrument, the six explanation contexts, the generation and parsing pipeline,
the text-only judge, and the analysis scripts that produce every table and
figure.

**No results and no datasets are included.** Every number in the paper is
regenerated by the reviewer with the steps below. `datasets/README.md` gives
the download link and expected format of each dataset. `research/results/`
does not exist in the bundle: the scripts create it on their first run, and
the analysis scripts stop with a short message if it is still empty.

## Layout

```
README.md                  this file
PROMPTS.md                 every prompt, copied from the code that ran
METHODS_NOTES.md           protocol decisions and the failures they fixed
requirements.txt           pinned versions of the environment that ran
datasets_config.yaml       per-dataset path, target column, task description
datasets/README.md         where to download the five datasets
.env.example               names of the API keys (generation only)

bb_metrics.py              the audit instrument: conditional precision + Hoeffding bound
lmpaxp_explainer.py        certified context (locally minimal PAXp, query access only)
cop_explainer.py           learned-rule contexts (COP, COP@k) with CP-SAT
run_calibration_nn.py      instrument check against exact ground truth (no LLM)
run_comparison_nn.py       the main pipeline: contexts, 3 strategies, parser, scoring
run_cop_sweep.py           COP length sweep (no LLM), used to pick COP@k*
run_judge.py               the text-only judge over the generated explanations

research/                  analysis: re-scoring under U/V/E, statistics, tables, audit
earlier_tiers/             decision-tree and boosted-tree tiers (Section 4, boosted-tree check)
```

Run every script **from this root directory**. The scripts import each other
and read `datasets_config.yaml` relative to the working directory, and they
create `research/results/` and write their outputs there.

## Setup

```bash
python -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
# put the five CSV files in datasets/ (see datasets/README.md)
cp .env.example .env    # only for the steps marked API below
```

## Free and paid steps

Some steps run locally. Others call commercial LLM APIs, **most of which are
paid**, and the cost is borne by whoever runs them.

| provider | used for | key in `.env` | cost |
|---|---|---|---|
| none | instrument, contexts, calibration, COP sweep, all analysis | none | free, local CPU |
| Together | generator (Llama-3.3-70B, GLM-5.2), **the pinned parser for every generator**, and the judge (default) | `TOGETHER_API_KEY` (up to three, rotated) | paid (pay-as-you-go) |
| Groq | generator (gpt-oss-120b), optionally the judge (`XAI_PROVIDER=groq`) | `GROQ_API_KEY` (up to three, rotated) | free tier with strict rate limits, paid tier otherwise |
| OpenAI | generator (gpt-5.6-terra) | `OPENAI_API_KEY` | paid |
| xAI | generator (Grok 4.20) | `XAI_API_KEY` | paid |
| Anthropic | generator (Claude Sonnet 5) | `ANTHROPIC_API_KEY` | paid |

Because the parser is pinned to Llama-3.3-70B on Together, a Together key is
needed for **any** generation run, whatever the generator. The free steps
need no key at all.

**Order of magnitude.** One instance costs about 44 LLM calls across the five
contexts and three strategies, roughly 16k tokens in total. One dataset × one
generator (15 instances, the default) is therefore about 250k tokens, and the
full paper grid (5 datasets × 6 generators, plus COP@k, COP@k* and the
judge's three passes) is a few tens of millions of tokens. Check each
provider's current price list before starting. Local steps are cheap except
the COP length sweep with `XAI_KMAX=18`, which took about 4.5 hours on
`cancer` on one CPU core.

**A cheaper partial reproduction.** One dataset with the Llama-3.3-70B
generator (one Together key) is enough to see the main finding: rule-shaped
contexts keep their precision through the text, attribution-shaped ones lose
it. Steps 1, 2, 3 and 5 below with `cancer` and `gridllama33` do this.

## Reproducing the study, step by step

| step | what | cost | command |
|---|---|---|---|
| 0 | self-tests of the instrument and the two rule solvers (a few minutes) | free | `python bb_metrics.py`, `python cop_explainer.py`, `python lmpaxp_explainer.py` (each prints `ALL PASS`) |
| 1 | instrument check against exact ground truth (§4, App. D.1) | free | `XAI_SAMPLER=U python run_calibration_nn.py cancer` and `XAI_SAMPLER=V python run_calibration_nn.py cancer` |
| 2 | generate the explanation grid (§5.1–5.3, §5.6) | **API, paid** | see *Generation* below, once per dataset × tag |
| 3 | re-score under the valid sampler V | free | `bash research/rescore_v.sh <tag>` |
| 4 | text-only judge, gpt-oss-120b, three passes (§5.4, Fig. 7) | **API, paid** (Together, or Groq) | `XAI_OUT_TAG=<tag> python run_judge.py` |
| 5 | statistics, tables, figures | free | `python research/stats_paired.py`, `python research/build_tab_models.py`, `python research/make_dialogue_outputs.py`, `python research/analyze_judge.py` |
| 6 | individual vs population guarantee (§5.5, Fig. 8, App. D.6–D.7) | free, then **API** | `XAI_KMAX=18 XAI_CSV_TAG=_V18 python run_cop_sweep.py <dataset>` for each dataset, `python research/cop_sampler_check.py`, then the `cop_best` generation below |
| 7 | cost model (App. D.8) | free (after step 2) | `python research/measure_token_cost.py` |
| 8 | compare the regenerated numbers with the paper | free (after steps 2–6) | `python research/audit_numbers.py` (add `--text` to also look for each number in the LaTeX sources, paths in `AUDIT_TEX`) |

`run_judge.py` refuses to judge a generator of the same family as the judge
(for the `gptoss120b` tag): it prints the reason and skips the dataset. Set
`XAI_JUDGE_MODEL` to another family, or `XAI_ALLOW_SELF_JUDGE=1` to run it as
a self-judge control.

To see the pipeline run end to end without spending anything, use
`XAI_NO_LLM=1` in step 2: the contexts are built and scored, and no API is
called.

The boosted-tree check of §4 (App. D.2, the uniform sampler scores a
sufficient reason at chance) has its own scripts in `earlier_tiers/`; see the
README there. The trace of App. C (cancer, instance 57) is written by step 2
with `XAI_SAVE_TRACES=1` (on by default) to
`research/results/nn_traces/cancer_gridllama33/inst_57.json`.

| paper | code |
|---|---|
| §3.4, App. A (conditional precision, Hoeffding ±4.3) | `bb_metrics.py` (`precision_hat`), `research/check_nn_feasible_sampling.py` (`precision_valid`, sampler V) |
| §3.2, Fig. 3, App. B.2 (the six contexts) | `lmpaxp_explainer.py`, `cop_explainer.py`, `build_arm()` in `run_comparison_nn.py` |
| §3.3, App. B.3–B.4 (three strategies, pinned parser) | `run_comparison_nn.py`, prompts in `PROMPTS.md` |
| §5.4, App. D.5 (judge) | `run_judge.py`, `research/analyze_judge.py` |

The `claim(...)` entries in `research/audit_numbers.py` are tagged with the
section numbers of an earlier draft. Correspondence with this paper: `4.1`,
`4.2` → §4; `4.3` → §5.1; `4.4`, `4.5` → §5.3; `4.6` → §5.5; `4.8` → §5.4;
`4.9` → §5.2 and §5.6; `6.x` → §6; `7.2` → Limitations; `A-*` → the appendix.

### Generation (step 2, API)

One run is one dataset × one generator. The six generators of the paper:

| tag | model id | `XAI_PROVIDER` |
|---|---|---|
| `gridllama33` | `meta-llama/Llama-3.3-70B-Instruct-Turbo` | `together` |
| `gptoss120b` | `openai/gpt-oss-120b` | `groq` |
| `gpt56` | `gpt-5.6-terra` | `openai` |
| `grok420` | `grok-4.20-0309-non-reasoning` | `xai` |
| `sonnet5` | `claude-sonnet-5` | `anthropic` |
| `glm52` | `zai-org/GLM-5.2` | `together` |

```bash
# five contexts (cop, lmpaxp, anchors, shap, lime), three strategies
XAI_PROVIDER=together XAI_OUT_TAG=gridllama33 \
  python run_comparison_nn.py cancer meta-llama/Llama-3.3-70B-Instruct-Turbo

# length-matched learned rule, run separately and merged into the same grid
XAI_ARMS=cop_k XAI_PROVIDER=together XAI_OUT_TAG=gridllama33 \
  python run_comparison_nn.py cancer meta-llama/Llama-3.3-70B-Instruct-Turbo
python research/merge_cop_arm.py cancer gridllama33 cop_k

# length-optimised learned rule (Llama-3.3-70B only, needs the k=18 sweep of step 6)
XAI_ARMS=cop_best XAI_PROVIDER=together XAI_OUT_TAG=gridllama33 \
  python run_comparison_nn.py cancer meta-llama/Llama-3.3-70B-Instruct-Turbo
python research/merge_cop_arm.py cancer gridllama33 cop_best
```

Repeat for the five datasets (`cancer`, `compas`, `diabetes`, `employee`,
`heart`) and the tags you can afford. Runs are resumable and checkpoint after
every instance, so an interrupted or rate-limited run can be restarted with the
same command. `research/rerun_dialogue.py` and `research/run_rerun_all.sh`
document how the dialogue column was regenerated after the refinement prompt
was fixed: they replay the contexts of an existing grid and only rewrite the
dialogue columns. They are not needed for a fresh run, which already uses the
fixed prompt.

Useful switches: `XAI_N_INSTANCES` (default 15), `XAI_NO_LLM=1` (contexts and
their precision only, no API), `XAI_ANCHOR_BATCH=10` (lower memory for
Anchors), `XAI_SAVE_TRACES=1` (per-instance JSON traces, on by default).
Reasoning models bill hidden reasoning tokens (about 1,100 before the first
visible token), so every generator runs with reasoning turned off where the
provider allows it.

## What to expect when rerunning

- The heuristic contexts (SHAP, LIME, Anchors) are reseeded before every
  instance, so every generator receives identical contexts.
- CP-SAT runs single-threaded with a fixed seed; COP rules are reproducible on
  the same machine, but equal-loss rules can differ across solver versions
  (`METHODS_NOTES.md` §4).
- LLM outputs are not bit-reproducible even at a fixed temperature. The
  findings the paper relies on (ordering by shape, near-zero loss for
  constructed rules, the judge's blindness within a method) are the quantities
  to compare, not individual cells. `research/audit_numbers.py` will
  therefore report some claims outside their tolerance on a rerun; the
  direction and size of the effects are what should match.
- `research/check_nn_feasible_sampling.py` rebuilds the classifier and checks
  that its recomputed uniform-sampler values match the ones written at
  generation time (maximum deviation printed as the *reproduction gate*). If
  the gate is not 0.00, the rebuilt model differs and later numbers are not
  comparable.

## Scope

Tabular data, binarizable features, query access to the classifier. No human
participants took part in any part of this work. The code is MIT-licensed; the
datasets remain under their own terms.
